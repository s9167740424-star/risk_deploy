# Включение парсера НСПД (второй бесплатный сервис на Render)

Теперь в проекте ДВА сервиса:
- riskcheck        — сайт (Flask + фронт), уже работает
- rosreestr-parser — парсер кадастра (FastAPI + Chromium), новый

Оба бесплатные. У каждого свои 512 МБ памяти, поэтому Chromium не мешает сайту.

## Что уже сделано за тебя
- render.yaml описывает оба сервиса
- parser-build.sh ставит зависимости парсера и Chromium
- в парсере порт читается из $PORT, добавлен флаг экономии памяти
- у основного сайта включён ROSREESTR_PARSER_ENABLED=1

## Шаг 1. Обновить репозиторий
В папке проекта на Mac (там же, где раньше):

    cd ~/Downloads/riskcheck-render   # или где лежит проект, привязанный к GitHub
    # СКОПИРУЙ СЮДА новые файлы из этого архива, ПОВЕРХ старых (с заменой):
    #   render.yaml, parser-build.sh,
    #   atlas-sales-backend/rosreestr-parser/  (папка целиком — там правленый main.py)
    git add .
    git commit -m "add rosreestr parser service"
    git push

Проще всего: распакуй этот архив и замени им содержимое папки проекта целиком, потом add/commit/push.

## Шаг 2. Render создаст второй сервис
1. Render увидит изменения в render.yaml и предложит применить Blueprint.
   Dashboard → Blueprints → твой блюпринт → он подхватит новый сервис rosreestr-parser
   (или зайди на страницу Blueprint и нажми Manual Sync).
2. Дождись, пока СБОРКА ПАРСЕРА пройдёт. Она дольше основной (ставится Chromium ~1-3 мин).
   Смотри Logs сервиса rosreestr-parser. Нужно дождаться строки вида:
       Browser initialized
       Uvicorn running on http://0.0.0.0:...
   и статуса Live.
3. Скопируй ПУБЛИЧНЫЙ адрес парсера — вверху его страницы, вида:
       https://rosreestr-parser-XXXX.onrender.com

## Шаг 3. Связать сайт с парсером (ОБЯЗАТЕЛЬНО)
1. Открой сервис riskcheck → Environment.
2. Найди переменную ROSREESTR_PARSER_URL (она пустая) и впиши туда адрес парсера
   из шага 2, БЕЗ слэша на конце:
       https://rosreestr-parser-XXXX.onrender.com
3. Сохрани. Render передеплоит riskcheck.

## Шаг 4. Проверка
- Парсер жив:  https://rosreestr-parser-XXXX.onrender.com/health  → {"status":"ok"}
- Сайт: открой Шаг 1 в интерфейсе, введи адрес — юридические данные (кадастр) должны подтянуться.

## Важно знать
- Оба сервиса на free-плане ЗАСЫПАЮТ после 15 мин простоя. Первый кадастровый запрос
  после сна будет долгим (~1 мин): просыпается и сайт, и парсер, плюс грузится тяжёлый
  сайт НСПД. Дальше быстрее. Таймаут запаса выставлен (90 сек).
- Chromium на 512 МБ работает на пределе. Если парсер иногда падает/перезапускается —
  это ожидаемо для бесплатного плана. Обычно восстанавливается сам.
- Если НСПД сменит вёрстку или не найдёт участок — парсер вернёт 404/503,
  сайт покажет, что юрданные недоступны, но не сломается.

## Если сборка парсера упала
Открой Logs сервиса rosreestr-parser и пришли ошибку. Частое:
- не хватило памяти при установке Chromium → Manual Deploy → Clear build cache & deploy;
- playwright не поставил системные зависимости → уже используем `--with-deps`, обычно ок.
